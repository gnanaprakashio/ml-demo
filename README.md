# House Price Prediction

A beginner-friendly Machine Learning web application that predicts the
approximate price of a house based on its features, built for a college
ML assignment.

---

## 1. Problem Statement

Buying or selling a house requires knowing a fair price. Manually
estimating a price by comparing similar houses is slow and inconsistent.
This project builds a model that learns the relationship between a
house's features (area, bedrooms, etc.) and its price, then predicts
prices for new houses automatically.

## 2. Objective

- Build and train a simple Linear Regression model on house data.
- Evaluate the model using standard regression metrics.
- Wrap the model in a Flask web app with a clean form-based UI so a
  user can enter house details and instantly see a predicted price.

## 8. Machine Learning Algorithm

### What is Linear Regression?
Linear Regression is a supervised learning algorithm that models the
relationship between one or more input features (X) and a continuous
output (y) by fitting a straight line (or hyperplane, in multiple
dimensions) of the form:

```
Price = w1*Area + w2*Bedrooms + w3*Bathrooms + w4*Floors + w5*Age + w6*Parking + b
```

Here `w1...w6` are the learned **coefficients** (weights) and `b` is
the **intercept**. The model finds the values of these weights that
best fit the training data.

### Why Linear Regression is suitable here
- The target (price) is a **continuous numeric value** — this is a
  regression problem, not classification.
- House price generally increases roughly proportionally with features
  like area and bedrooms, which is a **linear-ish relationship**.
- It's simple, fast to train, and easy to interpret and explain — ideal
  for a beginner/college-level assignment.

### Features and Target Variables
- **Features (X):** the input columns used to make a prediction —
  Area, Bedrooms, Bathrooms, Floors, Age, Parking.
- **Target (y):** the value we want to predict — Price.

### Train-Test Split
The dataset is split into:
- **80% Training set** — used to teach the model the relationship
  between features and price.
- **20% Testing set** — held back and used only to evaluate how well
  the model generalizes to unseen data.

### Cost Function
Linear Regression is trained by minimizing the **Mean Squared Error
(MSE)** between actual and predicted prices:

```
MSE = (1/n) * Σ (y_actual - y_predicted)²
```

The model adjusts its weights to make this value as small as possible
(scikit-learn does this internally using the Ordinary Least Squares
method).

### Model Evaluation Metrics
- **MAE (Mean Absolute Error):** average absolute difference between
  actual and predicted prices. Easy to interpret in the same units as
  price.
- **MSE (Mean Squared Error):** average of squared differences;
  penalizes larger errors more heavily.
- **RMSE (Root Mean Squared Error):** square root of MSE, back in the
  original price units — easier to interpret than MSE.
- **R² Score:** proportion of variance in price explained by the
  model (1.0 = perfect fit, 0 = no better than predicting the mean).

### How Prediction Works
1. User enters house details in the web form.
2. Flask reads and validates the form values.
3. Values are arranged into the same order used during training.
4. The saved model (`house_price_model.pkl`) predicts a price.
5. The predicted price is formatted (₹ with Indian-style commas) and
   displayed to the user.

  for exploring the data interactively (useful for your report/viva).

## Viva Questions and Answers

**Q1. What type of machine learning problem is this?**
A: It's a **supervised regression** problem — the model learns from
labeled data (features + known price) and predicts a continuous
numeric value (price).

**Q2. Why did you choose Linear Regression instead of a more complex model?**
A: The features have a roughly linear relationship with price, the
dataset is small and simple, and Linear Regression is easy to train,
interpret, and explain — appropriate for a beginner assignment. More
complex models can overfit on small/simple data and are harder to
justify without a clear accuracy gain.

**Q3. What is the difference between MAE, MSE, and RMSE?**
A: MAE is the average absolute error (easy to interpret, treats all
errors equally). MSE squares the errors before averaging, so it
penalizes large errors more. RMSE is the square root of MSE, bringing
the error back into the original price units, combining interpretability
with sensitivity to large errors.

**Q4. What does the R² score mean?**
A: R² measures how much of the variation in house prices is explained
by the model's features. An R² close to 1 means the model explains
most of the variation; an R² close to 0 means it explains very little.

**Q5. Why do you split data into training and testing sets?**
A: To evaluate how well the model performs on **unseen** data. If we
only tested on the training data, we couldn't tell whether the model
actually generalizes or has just memorized the training examples.

**Q6. How did you handle missing values?**
A: Missing numeric values were filled with the **median** of that
column, since the median is less sensitive to outliers than the mean.

**Q7. What is the cost function used in Linear Regression?**
A: Mean Squared Error (MSE) — the model finds coefficients that
minimize the average squared difference between actual and predicted
prices, using the Ordinary Least Squares method.

**Q8. What are coefficients in a Linear Regression model?**
A: Each coefficient represents how much the predicted price changes
when that feature increases by one unit, holding all other features
constant. For example, the `Area` coefficient tells us how much price
increases per additional square foot.

**Q9. How does the Flask app use the trained model?**
A: The model is trained once and saved to disk using Joblib
(`house_price_model.pkl`). The Flask app loads this file at startup,
so it doesn't need to retrain every time — it simply calls
`model.predict()` on the user's input to get a price.

**Q10. What would you do if the model's accuracy was too low?**
A: Investigate features (add more relevant ones or remove irrelevant
ones), check for and handle outliers, try feature scaling, or try a
more expressive model (e.g., Random Forest, Polynomial Regression)
and compare its evaluation metrics against Linear Regression.

**Q11. Why is data preprocessing important before training a model?**
A: Raw data often has missing values, duplicates, or inconsistent
formats that can confuse or bias a model. Preprocessing cleans the
data so the model learns real patterns instead of noise or errors.

**Q12. Can this model handle categorical features like "location"?**
A: Not directly — Linear Regression needs numeric input. Categorical
features would need to be converted using techniques like one-hot
encoding before being added to the model.
